## Running in 60 seconds

<Tabs>
<TabItem label="Serve a folder">

```bash
cd my-site && rws
```

Serves the directory on `http://localhost:7878` — `index.html`, directory
listings, ETags, gzip, byte ranges, and an optional SPA fallback for
client-side routers.

</TabItem>
<TabItem label="Automatic HTTPS">

```toml title="rws.config.toml"
port               = 443
http_redirect_port = 80

[acme]
domains = ["example.com", "www.example.com"]
email   = "you@example.com"
```

Certificates come from Let's Encrypt on first start and renew in the
background with zero-downtime reloads; HTTP redirects to HTTPS; HTTP/2 and
HTTP/3 are on. [How it works →](/features/acme/)

</TabItem>
<TabItem label="Reverse proxy">

```toml title="rws.config.toml"
[[upstream]]
name     = "app"
backends = ["localhost:3000", "localhost:3001"]

  [upstream.health_check]
  path = "/healthz"

[[route]]
  [route.match]
  path = "/api/*"

  [route.action]
  type     = "proxy"
  upstream = "app"

  [route.middleware]
  rate_limit = { max_requests = 500, window_secs = 60 }
```

Requests under `/api/` are load-balanced across healthy backends; everything
else falls through to the static files. Add `[acme]` for HTTPS in front.
[Config-driven proxy →](/proxy/config-driven/)

</TabItem>
</Tabs>

## What's inside

<CardGrid>
  <Card title="Automatic HTTPS" icon="approve-check-circle">
    Built-in ACME client: Let's Encrypt or a private CA, HTTP→HTTPS redirects, background renewal with hot reload, IPv4 and IPv6.
  </Card>
  <Card title="Reverse proxy & gateway" icon="setting">
    Load balancing, health checks, bearer / JWT / basic auth that fails closed, rate limits, caching, rewrites, IP filters — plus TCP, UDP, WebSocket, and gRPC proxying.
  </Card>
  <Card title="One TOML file" icon="document">
    Every setting lives in `rws.config.toml` (or env vars, or flags). Unknown keys are reported at startup instead of silently ignored.
  </Card>
  <Card title="No hyper, no Tower, no OpenSSL" icon="puzzle">
    HTTP/1.1, HTTP/2, routing, middleware, WebSocket, SSE, and the ACME client are implemented in-crate. HTTP/3 uses `quinn`; TLS uses `rustls`.
  </Card>
  <Card title="Kubernetes-ready" icon="rocket">
    `/healthz`, `/readyz`, Prometheus `/metrics`, graceful SIGTERM shutdown, and a Kubernetes Ingress watcher.
  </Card>
  <Card title="MCP server" icon="star">
    Expose tools, resources, and prompts to Claude and other AI agents over MCP Streamable HTTP with a builder API.
  </Card>
</CardGrid>

## Need custom logic? It's a Rust library

The server above is the `rust-web-server` crate. Use it directly for routes,
middleware, an MCP server, an ORM, background jobs, and more:

```toml title="Cargo.toml"
[dependencies]
rust-web-server = "18"
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
```

```rust title="src/main.rs"
use rust_web_server::prelude::*;

fn hello(_: &Request, _: &PathParams, _: &ConnectionInfo, _: &()) -> Response {
    Response::text(STATUS_CODE_REASON_PHRASE.n200_ok, "Hello, world!")
}

#[tokio::main]
async fn main() {
    let app = routes! {
        App::with_state(()),
        GET "/hello" => hello,
    };
    let (listener, pool) = Server::setup().unwrap();
    tokio::join!(
        Server::run_tls(listener, pool, app.clone()),
        Server::run_quic(app),
        Server::run_redirect(),
    );
}
```

## Build matrix

| | `http1` | `http2` | `http3` (default) |
|---|:---:|:---:|:---:|
| Runtime | sync thread pool | tokio | tokio |
| TLS | — | rustls | rustls |
| HTTP/2 | — | ALPN | ALPN |
| QUIC | — | — | quinn |
| MSRV | 1.88 | 1.88 | 1.88 |
