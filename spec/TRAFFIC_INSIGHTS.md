# Traffic insights in the admin UI

Written 2026-10-31, after a hand analysis of rws8.tech's access log (2.2
days, 32k requests: ~76% bots — half of them vulnerability scanners —
~18% AI crawlers and assistants, ~6% people). That took reverse DNS, RDAP
and published IP ranges because the JSON log had no User-Agent; 18.15
adds `host`, `user_agent` and `referer` to it. This plan puts the same
answer — who visits, split into **people**, **AI** and **bots** — on a
Traffic page of the admin UI, computed by rws itself. Target: **18.16.0**.

## What exists

- Every request passes `Log::log_access` (all protocols), which has the
  request, response and peer address.
- Admin API + UI (lit-material: stat tiles, table, chart), MCP tools via
  `admin::ops`, the access-log tail (500 lines) and `request_log` (100).
- No User-Agent knowledge, no visitor counting, nothing kept per day.

## Research

- **User-Agent lists**, both MIT, both pinned and regenerated by a script:
  - [ai.robots.txt](https://github.com/ai-robots-txt/ai.robots.txt)
    `robots.json`: 202 AI agents keyed by UA token, with `operator` and
    `function` (AI training crawlers, AI search crawlers, AI assistants /
    user-triggered fetchers, AI data scrapers).
  - [crawler-user-agents](https://github.com/monperrus/crawler-user-agents):
    1,505 bot patterns with tags (search-engine, seo, monitoring, social,
    feed…). Mostly literal tokens; the few real regexes are compiled to
    literal alternatives or dropped (counted by the script) — no `regex`
    dependency.
- **Verified crawlers** by published IP ranges (Google, Bing, Apple,
  DuckDuckGo, OpenAI GPTBot / OAI-SearchBot / ChatGPT-User, Perplexity,
  Common Crawl): a UA that claims one of them from elsewhere is a
  **spoofed bot** — common, and worth showing.
- **Unique visitors without storing IPs** — Plausible's scheme:
  `hash(daily_salt + host + ip + user_agent)`, salt rotated daily and
  forgotten, so a visitor can't be followed across days; aggregates only.
- **Behaviour** catches what lists miss: requests for `/.env`, `/.git/…`,
  `/wp-…` mark a scanner; no User-Agent at all is a bot; a browser UA that
  fetches pages but never their CSS/JS is a headless browser or a link
  preview, not a person (the hand analysis found ~1,400 such IPs).

## Proposed design

- **`traffic` module**, fed from `Log::log_access` (so it works without a
  log file and for every protocol), off the hot path's locks: a
  per-thread shard of counters merged on read, a classification cache per
  `(ip, user-agent)` per day (bounded, LRU).
- **Classification**, in order: internal (loopback, health checks) →
  verified crawler by IP range → AI by UA list → bot by UA list →
  scanner by path → spoofed (claims a known crawler, IP disagrees) → no or
  non-browser UA → bot; a browser UA that loads page assets → **person**,
  one that never does → "browser, no assets" (counted with bots,
  shown separately).
- **What's kept**, in hourly buckets (people / AI / bots × requests,
  page views, unique visitors) plus per-day top lists: pages (people),
  pages (AI), AI agents (name, operator, function), bot categories,
  referrer domains, 404s, hosts. No IPs or User-Agent strings of people;
  bot and AI names are kept (they're not personal data).
- **Admin API** `GET /traffic?range=24h|7d|30d&host=…` (JSON); **admin UI**
  Traffic page: three stat tiles (people, AI, bots — visitors and
  requests, change vs the previous period), a stacked chart per hour or
  day, tables for top pages, AI agents, bot kinds, referrers and 404s; a
  host filter. **MCP** tool `traffic_summary`.
- **Config** `[traffic]`: `enabled`, `retention_days`, `persist` (file),
  `exclude` paths; `rws --check`.
- **Performance budget**: ≤ 1% CPU per request in a same-run A/B; the UA
  match runs once per `(ip, ua)` per day.

## Decisions

User, 2026-10-31:
- **30 days, saved to a file**: hourly buckets kept 30 days, written to
  `[traffic] persist` (default `<state dir>/traffic.json`, e.g.
  `/var/lib/rws/traffic.json`) every few minutes and at shutdown, read back
  at start — restarts and upgrades keep the history.
- **Server side only**: UA lists, IP ranges, scanner paths and asset
  loading; no JavaScript beacon.
- **Bundled lists, refreshed each release**: generated by
  `ci/gen_bot_lists.py` from pinned upstream commits; the server makes no
  outbound requests for them.
- **On when the admin API is on** (`[admin] listen`); `[traffic] enabled =
  false` turns it off.
